# RPAI 課程大綱生成器

## 概述

依據講座基本資訊，同時產出兩份文件：

| 文件 | 對象 | 用途 |
|------|------|------|
| **客戶版課程大綱** `.docx` | 主辦單位 / 客戶 | 需求確認、報價附件、對齊期待 |
| **內部講師準備單** `.docx` | Eddy / Grace 等講師 | 素材清單、互動設計、可行性檢查、Show Muscle 準備 |

## Step 0：先找教學藍圖（2026-08 新增）

本 skill 是 `rpai-talk-blueprint` 的下游。開工前先檢查對話中或 outputs 是否已有教學藍圖（`*_教學藍圖.md`）：

- **有** → 直接讀取其受眾／目標／敘事主軸／五元素落點／時間骨架，**跳過重複詢問**，Step 1 只補藍圖缺漏的欄位（如報價、主辦資訊）。
- **沒有** → 若是完整的教學／講座規劃，建議先跑 `rpai-talk-blueprint`；使用者只要快速大綱時可直接進 Step 1。
- **課綱討論中若改動了藍圖層級決策**（主軸、段落、招牌），先回寫藍圖再繼續。

## Step 1：資訊收集

### 1-A 先從對話萃取

**在詢問之前，先掃描對話歷史**，主動推斷以下欄位：

| 欄位 | 推斷來源範例 |
|------|------------|
| 大主題 | 對話中提到的工具名稱、課程名稱 |
| 適合對象 | 「門市主管」「行銷人員」等職稱關鍵字 |
| 總時長 | 數字 + 小時/分鐘關鍵字 |
| 情境類型 | 「內訓」「公開班」「工作坊」等詞 |
| 客戶名稱 | 公司名稱、「幫 XX 做」等句型 |

已推斷的欄位直接使用，**不重複詢問**。

### 1-B 必填欄位智慧預設值

若對話中無法推斷，套用以下預設值，並在輸出時標註「（預設值，請確認）」：

| 欄位 | 預設值 | 說明 |
|------|--------|------|
| 情境類型 | 企業內訓 | RPAI 最常見的服務型態 |
| 學員人數 | 20–30 人 | 一般內訓班規模 |
| 語言 | 繁體中文 | 台灣市場主要語言 |

### 1-C 缺必填欄位時：一問一答

若仍缺少以下必填欄位，**每次只問一個問題**，不全部列出：

**必填欄位優先順序：**
1. 大主題（課程名稱或主軸）
2. 總時長
3. 適合對象
4. 講座目標（學員的核心收穫）

> 範例問法：「這次課程的主題是什麼？例如：ChatGPT 實戰應用、AI 工具導入等。」

### 1-D 完整欄位清單

| 欄位 | 說明 | 必填 |
|------|------|------|
| 大主題 | 課程名稱或主軸 | ✅ |
| 適合對象 | 學員職位或背景 | ✅ |
| 總時長 | 含休息的課程總長 | ✅ |
| 講座目標 | 學員的核心收穫（1–3 句） | ✅ |
| 學員人數 | 影響互動設計 | 建議 |
| 情境類型 | 見下方說明 | 建議 |
| 客戶/主辦單位 | 文件標題用 | 可選 |
| 特殊需求 | 指定工具、禁忌話題、場地限制 | 可選 |

## Step 2：規劃架構

### 2-A 時間分配

| 總時長 | 建議單元數 | 休息安排 |
|--------|-----------|---------|
| 1 小時 | 2–3 單元 | 無休息 |
| 1.5 小時 | 3–4 單元 | 無休息或 5 分鐘 |
| 2 小時 | 4–5 單元 | 1 次 10 分鐘 |
| 3 小時 | 5–6 單元 | 1 次 10–15 分鐘 |
| 4 小時 | 6–8 單元 | 上下半場各 10 分鐘 |
| 半天（4.5h） | 7–9 單元 | 2 次 10 分鐘 + 中間緩衝 |
| 全天（6h） | 9–11 單元 | 上下午各一次 + 午休 |

> 休息時間不列入表格，在時長欄備注即可。

### 2-B 情境類型與教學方式

| 情境類型 | 說明 | 常用教學方式 |
|---------|------|------------|
| 企業內訓 | 封閉班、固定學員 | 案例說明、講師示範、小組討論、演練實作 |
| 對外公開講座 | 開放報名、異質學員 | 案例說明、講師示範、互動問答（Slido/Mentimeter） |
| 工作坊 / Workshop | 強調產出、動手做 | 個人演練、小組討論、成果發表、同儕回饋 |
| 線上課程 | 非同步、自學為主 | 預錄影片、測驗、討論區互動、作業提交 |
| **混合型**（內訓+工作坊） | 前半講授、後半實作 | 前段：案例+示範；後段：演練+發表 |
| **混合型**（講座+互動） | 有感知識傳遞 | 前段：故事+數據；中段：小組討論；後段：QA |

### 2-C 課程結構模板

根據講座目標，選擇合適的結構模板：

#### 三段式（痛點→工具→實作）
適合：工具導入類、技能培訓
```
1. 開場暖身（破冰 + 現況痛點）
2. 工具介紹與示範（講師示範 + 即時演練）
3. 實作收尾（個人/小組演練 + 成果分享）
```

#### 知識疊加式（Why→What→How→Now What）
適合：觀念建立類、策略思維
```
1. 為什麼重要（數據 + 趨勢 + 故事）
2. 是什麼（概念 + 框架說明）
3. 怎麼做（工具 + 步驟演示）
4. 我能做什麼（行動計畫 + 承諾）
```

#### 挑戰解決式（情境→拆解→解法→驗證）
適合：問題導向、工作坊
```
1. 情境導入（真實案例 / 角色扮演）
2. 問題拆解（小組討論）
3. 解法提案（工具應用）
4. 驗證與優化（成果發表 + 回饋）
```

#### 故事敘事式（Before→Struggle→After→Bridge）
適合：激勵型講座、高階主管場合
```
1. 現狀描繪（Before：現在的困境）
2. 關鍵轉折（Struggle：遇到什麼改變）
3. 美好願景（After：轉型後的樣貌）
4. 如何抵達（Bridge：RPAI 如何幫助）
```

### 2-D「有趣、有感、有料」設計原則

每份課綱規劃時，主動在以下時機點安排**互動或節奏調節**，避免單向講授超過 20 分鐘：

| 設計類型 | 說明 | 常見形式 |
|---------|------|---------|
| **有趣**（體驗感） | 讓學員「動起來」，打破被動聆聽 | 舉手投票、快問快答、角色扮演、AI 即時試玩 |
| **有感**（共鳴感） | 與學員的工作現場連結 | 案例討論、痛點問答、「你們公司有沒有？」 |
| **有料**（密度感） | 帶走可執行的工具或框架 | Prompt 模板、checklist、一頁摘要、工具清單 |

> 每個單元至少涵蓋以上其中一種。工作坊或半天以上課程，三種都應出現。

### 2-E 五欄表格填寫規範

| 欄位 | 填寫規範 |
|------|---------|
| **單元名稱** | 4–10 字，反映核心（例：Prompt 設計實戰） |
| **學習目標** | 條列 2–4 點，使用「掌握/學會/能夠/了解」開頭 |
| **教學方式** | 1–2 種（案例說明 / 講師示範 / 小組討論 / 演練實作 / 互動問答 / 總結QA） |
| **成果** | 具體產出或能力，格式：「掌握 OO」或「產出 1 份 OO」 |
| **分鐘** | 純數字，所有單元加總 = 總時長 − 休息時間 |

### 2-F 課程介紹撰寫規範

- 共 **3 個要點**，條列式
- 每點結構：**學員痛點 → 課程如何解決 → 具體收穫**
- 語氣：專業親切，第二人稱「學員/你」為主
- 禁止過度行銷用語；強調實務落地

## §4 Show Muscle 備戰清單（內部準備單專用）

**定義：** Show Muscle 是指在課程中讓學員或客戶感受到「RPAI 遠不只是工具教學，而是有深度的教育設計夥伴」的時刻，目的是提升後續合作意願。

每份講師準備單都應在 Show Muscle 備戰清單中，針對以下三個層次各準備至少一個「炸場時刻」：

### 層次一：知識深度（讓人覺得「你們懂的比我多」）
準備一個**對象行業的痛點數據或洞察**，在課程開場或轉折點拋出。

範例：
- 「根據 LinkedIn 2024 學習報告，企業 L&D 部門 72% 的時間花在製作教材，而非設計學習體驗。」
- 「Gartner 預測，2025 年 69% 的例行性管理任務將由 AI 自動化完成。」

寫法：`在第 X 分鐘，拋出這句話：「___」，然後問：「你們目前的比例大概是多少？」`

### 層次二：工具整合力（讓人覺得「他們比我更懂怎麼用」）
準備一個**跨工具串聯示範**，展示單一工具做不到、但組合起來可以的效果。

範例組合（依課程工具調整）：
- NotebookLM 提取知識點 → ChatGPT/Claude 寫教案 → Gamma 生成簡報
- Make 串接表單 → 自動寫入試算表 → 發送 Slack / Email 通知
- n8n 監控網頁變化 → 觸發 GAS 整理資料 → 自動生成報表

寫法：`在第 X 分鐘，執行串聯示範：[步驟1] → [步驟2] → [步驟3]，預計耗時 Y 分鐘，強調「這個流程以前要半天，現在 15 分鐘」`

### 層次三：教學設計專業度（讓人覺得「他們不只是教工具」）
在課程中嵌入一個**教育理論框架或行業洞察**，並直接對應到工具使用情境。

建議切入（選一個嵌入）：
- **Bloom's Taxonomy**：示範「AI 能幫你把課程從記憶層提升到應用層」
- **70-20-10 法則**：說明自動化如何放大 70% 工作中學習的效率
- **流程成熟度模型**：從手動 → 半自動 → 全自動的三段成熟度，幫學員定位自己的現況

寫法：`在第 X 分鐘說：「讓我借用一個框架來解釋——」展示框架圖，花 3 分鐘，結束後說：「這就是為什麼我們設計這堂課的順序是這樣。」`

### 加分項：後續合作鉤子（每堂課必備）
最後 5 分鐘展示「RPAI 後續服務地圖」：
- ① 本次工作坊（已完成）
- ② 進階認證計畫 / 自動化工作坊
- ③ 企業客製化導入輔導
- ④ AI 教材 / 自動化流程代製服務

說法：「如果今天有任何收穫，歡迎跟我們談下一步——是真的可以幫你把今天學到的，落地到你們的工作流程裡。」

**Show Muscle 規範：三個層次各至少一條，不可留空。**

| **n8n** | 開源自動化平台 | 自架免費；雲端有免費方案 | 技術型學員；需要更高彈性的串接邏輯 | 自架版需伺服器，課堂建議用雲端試用版 |
| **GAS**（Google Apps Script） | Google 生態系腳本 | 完全免費 | Gmail/Sheets/Forms 自動化；適合已用 Google Workspace 的企業 | 需基本 JavaScript 概念；建議用範本降低門檻 |
| **VBA** | Office 桌面腳本 | Excel/Word 內建免費 | Excel 報表自動化；老牌企業環境常見需求 | 無需安裝；但僅限 Windows Office，Mac 支援有限 |

> **課堂建議選工具邏輯：**
> - 學員用 M365 → Power Automate（雲端版先教，桌面版示範）
> - 學員用 Google Workspace → GAS + Make
> - 學員為技術背景 → n8n
> - 學員為非技術一般企業 → Make（視覺化最友善）
> - 學員需要 RPA 重型操作（ERP/桌面應用）→ UiPath + Power Automate 桌面版

## Gotchas（常見陷阱）

1. **分鐘數加總**：所有單元分鐘 ≠ 含休息總時長；須扣除休息後對齊教學時數
2. **學習目標換行**：用多個 `Paragraph` 取代 `\n`，否則 docx 格式破版
3. **表格欄寬合計**：`columnWidths` 之和必須等於 `width.size`，否則右側邊框消失
4. **字體回退**：微軟正黑體在 Linux 容器無法渲染預覽，但 .docx 在 Windows/Mac 正常
5. **客戶名稱為空**：標題只顯示課程名稱，不加 `｜`
6. **工作坊情境**：至少一個單元設定「演練實作」或「小組討論」，成果欄要有具體產出物
7. **混合情境時長分配**：前段講授不超過總時長 60%，後段實作/互動至少 40%
8. **互動間隔**：單向講授連續超過 20 分鐘時，主動在課綱中安排互動節奏
9. **可行性清單**：課程含需帳號工具（Make / n8n / Power Automate / Gamma / NotebookLM 等），準備單中務必填入帳號需求與備案
10. **兩份文件同時產出**：不可只輸出客戶版，講師準備單為標配輸出
11. **Show Muscle 必須有**：講師準備單中的 Show Muscle 備戰清單為必填，三個層次各至少一條，不可留空
12. **客戶版必含講師資訊與報價區塊**：參考 ASML 版型，每份客戶版大綱結尾必須附上 Eddy 講師簡介與報價資訊表格，這是標準交付格式
