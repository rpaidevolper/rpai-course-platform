# RPAI 簡報製作 Skill

## 依賴關係

- `rpai-brand-guidelines`：品牌色彩、語氣規範（色彩唯一源頭）
- `pptx`：pptxgenjs 技術實作（透過 `Skill: anthropic-skills:pptx` 呼叫）

> **字級與字重：簡報場景由本 skill 管轄（brand-guidelines「媒介分層」已明文授權，非片面覆寫）。** brand-guidelines 的 Type Scale 適用於網頁與社群；簡報一律依本 skill 的「兩條硬規則」與字級表。**色彩、語氣、字型家族仍以 brand-guidelines 為唯一源頭。**

# 第零層：兩條不可違反的硬規則（最高優先）

> 這兩條凌駕一切。任何一頁、任何一個文字元素，違反就是錯誤，產出前後都要逐頁自檢。

## 硬規則 1：全文粗體

**每一個文字元素都必須 `bold: true`。** 沒有例外——標題、正文、卡片內文、技術標籤、頁尾浮水印、頁碼、表格儲存格、箭頭符號，全部粗體。

```javascript
// 封裝一層，從源頭杜絕漏網
function T(text, opts = {}) { return { text, options: { bold: true, fontFace: "Microsoft JhengHei", ...opts } }; }
// 所有 addText 一律帶 bold: true
s.addText("分行業績月報彙整", { bold: true, fontFace: "Microsoft JhengHei", fontSize: 18, ... });
```

## 硬規則 2：最小字級 16pt

**頁面上不得出現任何小於 16pt 的字。** 含頁尾、頁碼、來源標註、表格內文、圖說——全部 ≥ 16pt。唯一例外是「段落分頁的超大浮水印數字」（那是裝飾，往大走，200pt）。

> **密度後果（務必內化）**：16pt 地板會讓每頁能放的字大幅變少。一般簡報多數正文落在 12–14pt，全部拉到 16pt 後可放的字明顯變少——**寧可多拆一頁，也不要硬塞**。每頁正文濃縮成短句、條列每條一行、卡片每張 2–3 行封頂。這正好呼應第一層「乾淨優先 / 每頁一個錨點」。

## 自檢（產出後逐頁掃描）

```bash
# 掃出任何 <16pt 或非粗體的文字 run（應為 0）
python3 - <<'PY'
import re,glob
bad_sz=bad_b=0
for f in glob.glob('unpacked/ppt/slides/slide*.xml'):
    x=open(f,encoding='utf-8').read()
    for rpr in re.findall(r'<a:rPr\b[^>]*>', x):
        m=re.search(r'sz="(\d+)"',rpr)
        if m and int(m.group(1))<1600: bad_sz+=1          # <16pt
        if 'b="1"' not in rpr: bad_b+=1                    # 非粗體
print("小於16pt:",bad_sz,"｜ 非粗體:",bad_b,"（兩者都應為 0）")
PY
```

# 視覺基準：預設視覺風格

> 這是本 skill 的**預設視覺目標**。新簡報若無特別指定，就照這套做，維持整體一致。

**核心 DNA**：深淺交替節奏（深色封面/分頁 ↔ 淺色內容頁）、以色階層次取代邊框、每頁一個視覺錨點、大量留白。畫布固定 `LAYOUT_WIDE`（13.33×7.5）。

**版型詞彙（canonical layout set）**——產出時從這套挑，不要每頁都同一種：

| 代號 | 版型 | 場景 | 底 |
|------|------|------|----|
| D1 | 封面 | 開場 | Navy |
| D2 | 段落分頁 | 單元起點（Teal 200pt 浮水印數字 + 40pt 標題） | Navy |
| D3 | Q&A / 結語 | 收束 | Navy |
| D4 | 休息 / 午休 | 過場 | Navy |
| L1 | 沉浸情境 | 一句關鍵句置中 | Ash |
| L2 | 三欄卡片 | 並列概念（≤3） | Ash |
| L3 | 步驟流程 / Demo | 操作步驟 | Ash |
| L4 | 左右對比 | A vs B | Ash |
| L5 | 編號列表 | 重點帶走、條列 | Ash |
| L6 | 2×2 四格 | 四象限分類 | Ash |
| L7 | 工作表格 | 盤點卡、提案表 | Ash |
| L8 | Demo＋備忘 | 講師示範頁（右側備忘欄） | Ash |
| L9 | 帶走清單 | 單元小結（3 點） | Ash |

**鎖定的視覺 token（預設標準，勿漂移）：**

- **段落分頁浮水印**：`#7AFFF5` Teal，200pt，`transparency: 86`，靠右；左側 Teal 細條 `w:0.06`；標題 40pt White。
- **編號圓圈（淺色頁）**：**預設用強調寫法 → White 底 + Navy `#011455` 1.5–2.5pt 描邊圈 + Navy 數字**（帶走頁 / 重點頁一律用此，避免太弱）；純分區、非重點時才降為 IceD `#DBEAEE` 底圈 + Navy 數字。**禁止 Navy 實心圓當數字底（填色面禁止）**。依據 brand-guidelines「淺色頁強調層級」。
- **卡片**：White `#FFFFFF` 底，放在 Ash 背景上；陰影用 **Navy `#011455` 調色**（`blur:16, offset:3, opacity:0.06`），**不用純黑 `#000000`**（一律 Navy 調色）。
- **Icon 色塊**：Navy 底 `#011455`／`#011C67` + Teal/Sky 符號，或 Surface 底圈 + Navy 符號；符號用 Unicode 幾何字（● ◆ ▶ ✎ ✓ → ›），不用 emoji。

**功能色（僅必要時、計入每頁三色預算）：**

| 用途 | 色 | 場景 |
|------|----|------|
| 警示 / 紅線 | `#CC3333` | ✗、禁止事項、資安紅線（作文字或細條，不做大色塊） |
| 重點高亮 | `#2563EB` / `#38BDF8` | 連結、強調、深底點綴 |

# 第一層：設計哲學

> Claude 讀完這一層就應該知道「什麼感覺是對的」。
> 這五條原則的優先級高於所有技術規範，衝突時以原則為準。

### 原則 1：乾淨優先

寧可少放一個元素，也不要讓版面顯得擁擠。
如果猶豫要不要加裝飾，答案是不加。
簡潔 ≠ 空白——是每個元素都有存在的理由。

### 原則 2：每頁一個視覺錨點

觀眾看到這頁時，3 秒內能知道重點是什麼。
可以是一個大數字、一句關鍵句、一組對比、一張圖。
不能是「六個並排的同樣大小卡片」——那等於沒有重點。

### 原則 3：版型跟著內容走

不存在「預設版型庫」。根據這一頁要傳達什麼，當下判斷最適合的排版方式。
**避免連續兩頁使用相同排版結構，除非是同一系列（步驟頁、比較頁）刻意形成的視覺節奏。**
思考順序：這頁的核心訊息是什麼 → 什麼排版方式最能傳達 → 執行。

### 原則 4：間距是設計的一部分

間距不是「填完內容後剩下的空間」。
標題與內容之間、項目與項目之間、頁面邊緣與內容之間，都需要有意識地設定。
太擠和太空都是問題。

### 原則 5：圖片 / Icon 是加分項，不是必需品

能加就加，加不了就留佔位框並標明建議素材。
不要為了「有圖」而硬放一個不相關的裝飾。
佔位框格式：虛線框 + 框內標註建議圖片類型與尺寸。

### 反面案例警示（❌ 不該做的事）

以下是過去實際產出後被退回的問題，Claude 必須避免重蹈覆轍：

**版面僵硬**
❌ 每頁都套同一種三欄卡片 layout → 「整體太過僵硬，都是同一個版面的感覺」
❌ 連續 3 頁以上使用相同排版結構（同一系列除外）

**間距失控**
❌ 內容只佔頁面 40%，其餘全空白 → 「有過多不必要的留空」
❌ 間距忽大忽小，沒有一致的節奏 → 「有些間距不用拉那麼大或那麼密」

**封面過度設計**
❌ 封面放了同心圓幾何 + Unit 列表 + 網址 pill + 日期 badge
→ 封面應該只有：主題、講者、品牌標記
→ 「封面不用那麼複雜，很明確今天的主題是甚麼就可以」

**字體層級錯誤**
❌ 強調的標題字體卻很小，跟說明文字差不多大
→ 標題必須是頁面上視覺權重最大的文字元素之一
❌ 深色背景上用灰色文字 → 深色背景統一用白色文字

**強調不足（該強調卻沒強調）**
❌ 帶走頁 / 轉折句 / 關鍵數字只用 IceD 淡底 → 觀眾看不出重點在哪、跟白卡黏在一起
→ 淺頁強調一律升級為 **Navy 線性強調**（描邊圈 / 左強調條 w≤0.1吋 / 大字），見上方「淺色頁強調」與 brand-guidelines

**修改時過度補償**
❌ 為了修正「太空白」而塞入大量裝飾元素，結果失去原本的簡潔感
→ 修改時要克制，不是「加東西」而是「調整已有的」
→ 「這版文字好，上一版排版比較乾淨好看」（v2 文字 + v1 排版 = v3）

**資訊呈現方式不當**
❌ 用箭頭表達不適合階段概念的內容
❌ 一頁同時塞兩個不同主題（例如：模組化概念 + 客戶案例）
→ 每頁應該聚焦在一件事上

# 第二層：決策流程

## Step 0：生成前確認（每次必做）

**先找上游文件（2026-08 新增）**：檢查對話中或 outputs 是否已有教學藍圖（`*_教學藍圖.md`）或課程內容腳本（`*_課程內容腳本.md`）：
- **有腳本** → 逐頁結構、版型、講稿核心直接沿用；逐字稿在此階段展開進 speaker notes。區塊 A/B/C 只補缺漏。
- **只有藍圖** → 讀取受眾／目標／敘事主軸，區塊 A/B 不重問。
- **都沒有** → 照下方三區塊正常確認。
- 簡報製作中若改動了藍圖層級決策，先回寫教學藍圖再繼續。
- 視覺一律依 rpai-brand-guidelines 組織主視覺；外部風格參考屬一次性例外，需使用者明示，且不回寫品牌規範。

在開始任何程式碼或設計之前，先向使用者確認以下三個區塊。
若使用者已提供部分資訊，只問尚未確認的部分。
所有項目對齊後，才進入 Step 1。

### 區塊 A：講者資訊
- 講者姓名與職稱？
- 是否需要講者介紹頁？（有的話請提供 2-4 行簡介）
- 單一講者 or 多位講者？

### 區塊 B：受眾與目標
- 這場簡報的受眾是誰？（職位、背景、技術程度）
- 受眾看完後，你希望他們：知道什麼？感受什麼？採取什麼行動？

### 區塊 C：內容與格式
- 大綱或主題確認（若使用者已提供，確認是否完整）
- 預估頁數範圍（預設 15-25 張）
- 有沒有必須放入的素材（截圖、Logo、數據圖表）？
- **敘事模型選擇（必做，不可跳過）**：根據主題與目標，主動從「附錄：敘事模型清單」挑出 2-3 個最適合的候選，為每個候選產出「3-5 頁敘事骨架預覽」供使用者拍板。

### 敘事模型推薦格式

為每個候選模型輸出以下內容，讓使用者能直接比較：

```
【候選 1：<模型名稱>】
為什麼適合這場講座：<1-2 句話說明模型特性與本次主題的契合點>

敘事骨架預覽（3-5 頁）：
P1. <頁面標題> — <一句話說明這頁要傳達什麼>
P2. <頁面標題> — <一句話說明這頁要傳達什麼>
P3. <頁面標題> — <一句話說明這頁要傳達什麼>
...

適合的氛圍：<分析型 / 說服型 / 行動導向 / 探索型 ...>
```

**推薦原則**：
- 永遠主動推薦，不要反問「你想用什麼模型」
- 候選之間必須有明顯差異（例如：一個分析型 + 一個說服型 + 一個行動型），不要三個都是類似調性
- 如果主題明顯偏某個方向，可以只推 2 個而不是硬湊 3 個
- 骨架預覽用「這頁要傳達什麼」而不是「這頁叫什麼」——目的是讓使用者看到敘事流動

### 確認閘門

確認完畢後，Claude 輸出「簡報藍圖摘要」供使用者確認，**格式如下**：

```
【簡報藍圖摘要】
受眾：___，目標：___（知道什麼／感受什麼／採取什麼行動）
敘事模型：___（從候選中選定的模型名稱）
頁數：約 __ 張

| # | 頁面標題 | 目的（一句話） | 備註 |
|---|---------|--------------|------|
| 1 | 封面 | 建立主題期待感 | - |
| 2 | ... | ... | ... |

敘事邏輯：___（說明這份簡報如何實踐所選模型）
視覺方向：___（配色、氛圍）
```

**使用者確認後才進入程式碼階段。不要跳過這個步驟。**

# 第三層：視覺系統全域規則

> 色彩規範以 `rpai-brand-guidelines` 為唯一源頭。
> 以下只定義簡報場景的應用規則。

## 配色上限：每頁不超過三種色彩

這是硬性規則。**重點：限制是「每頁」，不是「整份簡報」**——整份簡報可以用到深底頁 + 淺底頁兩套配色，但**任何一頁單獨看**都不能超過三種色彩（含背景）。

60-30-10 法則：60% 主色（背景）、30% 輔助色（標題/結構）、10% 點綴色（強調）。

### 常見誤解

「每份簡報三色」是錯誤理解。正確是：
- 淺底頁（例如白底 + Navy 文字 + Primary Blue 點綴）= 3 色 ✓
- 深底頁（例如 Navy 背景 + White 文字 + AccentDark 點綴）= 3 色 ✓
- **但同一張深底頁上不能再加第四個色**（例如不要在深底加橙色警示）

### 深底 / 淺底強調色可以不同

深底頁的點綴色（例如 `#38BDF8`）可以跟淺底頁的點綴色（例如 `#2563eb`）不同——這不違反規則，因為它們從來不會出現在同一頁。

## 字體

統一使用 `微軟正黑體`（Microsoft JhengHei）。
pptxgenjs 中寫為：`fontFace: "Microsoft JhengHei"`。

## 字體層級（全粗體，最小 16pt — 見第零層硬規則）

> 下表所有層級 **一律 `bold: true`**，且 **沒有任何值低於 16pt**。

| 層級 | 用途 | 字號 | 粗細 | 行距 |
|------|------|------|------|------|
| 封面主標 | D1 封面 | 40pt | **Bold** | 1.1 |
| 段落分頁標題 | D2 | 40pt | **Bold** | 1.2 |
| 浮水印數字 | D2 裝飾 | 200pt（Teal, transp 86） | **Bold** | 1.0 |
| H1 頁面主標題 | 內容頁標題 | 26–30pt | **Bold** | 1.3 |
| H2 卡片 / 項目標題 | | 18–22pt | **Bold** | 1.2 |
| Body 正文 | 說明文字 | 16–18pt | **Bold** | 1.4 |
| 標籤 / 來源 / 圖說 | metadata | **16pt（地板）** | **Bold** | 1.2 |
| 頁尾 / 頁碼 | 浮水印 | **16pt（地板，以透明度弱化）** | **Bold** | 1.0 |

標題必須是頁面上視覺權重最大的文字元素之一。
弱化元素（頁尾、來源）**靠透明度（transparency）退場，不靠縮小字級**——因為字級不能低於 16pt。

## 每頁資訊密度上限（16pt 地板下從嚴）

16pt 地板下，每頁能容納的字明顯變少。**寧可多拆一頁。**

- 條列式：最多 **4** 條，每條 **1 行**（不超過約 20 字）
- 卡片內文：每張卡 **2–3 行**封頂
- 說明文字：每區塊不超過 **2** 行
- 一頁只講一件事；內容超過上限就強制拆兩頁

## 浮水印

統一為「RPAI 數位優化器」，置中在頁面最底部。
pptxgenjs 設定：`x: 0, w: "100%", align: "center", y: 7.05`，**16pt、bold: true**，以 **transparency: 55–65** 弱化（不縮小字級）。
不放在左上、右上或任何其他位置。

## 頁碼

純數字（例如：1、2、3），右下角，**16pt、bold: true**，以透明度弱化。
不需要「第 X 頁」或「X / Y」格式。

## 封面規則

封面只放：
- 主題標題（大）
- 副標題或日期（小，選放）
- 講者姓名（若適用）
- 品牌標記（RPAI 數位優化器，右上角或其他不搶眼位置）

封面不放：同心圓幾何、Unit 列表、網址 pill、過多裝飾元素。

## 不需要副標題行

內容頁不加副標題行（主標題下方的灰色說明行）。
統一一個主標題就好，主標題可以大一些。

## 淺色頁強調（該強調就要強調）

> 依據 `rpai-brand-guidelines`「淺色頁強調層級」。這條是為了根治「明明該強調卻沒強調」——過去只用 IceD，淡到跟白卡黏在一起。

**IceD `#DBEAEE` 只負責「分區」，不負責「強調」。** 需要被觀眾記住 / 停留的元素（帶走頁重點、轉折句、關鍵數字、章節重點），一律升級為 **Navy 線性強調**：

- **描邊圈**：White 底 + Navy 1.5–2.5pt 外框 + Navy 數字（數字圈預設）
- **左強調條**：白卡左側 Navy 直條，`w ≤ 0.1`（是線，不是面）
- **大字數字**：Navy 大號 01/02/03，去圈，靠字級製造重量

**判準**：目的是「被記住」→ Navy 線性強調；只是「分層」→ 才用 IceD。**一頁只要有重點 / 帶走 / 轉折 / 關鍵數字，至少要有一處 Navy 線性強調。**

**仍禁止**：Navy 實心圓、Navy banner、Navy 大色塊等任何「填色面」。要更強衝擊時，正解是把整頁改成深色頁（Navy 底 + Teal 強調），不是在淺頁塞 Navy 色塊。

```javascript
// 數字描邊圈（淺色頁強調寫法）—— 取代弱的 IceD 底圈
s.addShape(pres.shapes.OVAL, {
  x, y, w: 0.5, h: 0.5,
  fill: { color: "FFFFFF" },                 // 白底，不是 Navy 實心
  line: { color: "011455", width: 2 },       // Navy 描邊 = 強調（線，非面）
});
s.addText("1", { x, y, w: 0.5, h: 0.5, color: "011455", bold: true,
  fontSize: 20, align: "center", valign: "middle", fontFace: "Microsoft JhengHei" });

// 轉折句 / 關鍵句：白卡 + Navy 左強調條（w ≤ 0.1，是線不是面）
s.addShape(pres.shapes.RECTANGLE, { x: 0.6, y, w: 0.08, h: 0.6, fill: { color: "011455" }, line: { type: "none" } });
```

## 淺底頁背景層次

**純白 `#FFFFFF` 當淺底頁背景會顯得單調乏味**——大量內容頁（20+ 張）連續用純白，觀眾會覺得簡報很「陽春」、沒有設計感。

### 預設做法（方向 B）

- 背景：`#F8FAFC`（微灰藍白，幾乎看不出差別但不是純白）
- 全頁淡網格：`#E2E8F0`，線寬 0.5pt，70% 透明度，每 0.5" 一條（垂直 + 水平）
- 右上角小裝飾：兩條短斜線 `#2563eb`，40-60% 透明度

網格在投影機上仍可見但不搶戲，提供「這頁被設計過」的質感。

### 實作片段

```javascript
function lightSlide() {
  const slide = pres.addSlide();
  slide.background = { color: "F8FAFC" };

  // 網格
  for (let x = 0.5; x < 13.33; x += 0.5) {
    slide.addShape(pres.shapes.LINE, {
      x, y: 0, w: 0, h: 7.5,
      line: { color: "E2E8F0", width: 0.5, transparency: 70 },
    });
  }
  for (let y = 0.5; y < 7.5; y += 0.5) {
    slide.addShape(pres.shapes.LINE, {
      x: 0, y, w: 13.33, h: 0,
      line: { color: "E2E8F0", width: 0.5, transparency: 70 },
    });
  }

  // 右上角裝飾
  slide.addShape(pres.shapes.LINE, {
    x: 12.3, y: 0.35, w: 0.6, h: 0,
    line: { color: "2563EB", width: 2, transparency: 40 },
  });

  return slide;
}
```

**注意**：網格函式只套用在淺底頁，深底頁保持純色背景——深底頁本身的色彩力量足夠，加紋理反而會干擾。

## Icon 色塊風格（比純文字卡片有設計感）

卡片中純標題 + 文字容易看起來乏味。使用 **Navy 底色塊 + AccentDark 符號** 的 icon 風格可以大幅提升質感：

```javascript
// Icon 色塊：左上角 0.55 × 0.55 吋
s.addShape(pres.shapes.RECTANGLE, {
  x: cardX + 0.3, y: cardY + 0.25, w: 0.55, h: 0.55,
  fill: { color: "011c67" }, line: { type: "none" },
});
s.addText("✎", {
  x: cardX + 0.3, y: cardY + 0.25, w: 0.55, h: 0.55,
  fontSize: 20, color: "38BDF8",
  bold: true, align: "center", valign: "middle", margin: 0,
});
```

**符號選擇**：優先用 Unicode 幾何符號（● ◆ ▤ ▶ ✎ ✓ ↓ ↑ →）——比 emoji 穩定，比引入 react-icons 輕量，在 LibreOffice/PDF 轉換都能正常渲染。

# 第四層：技術防線 / Gotchas

## pptxgenjs API 陷阱

| 陷阱 | 正確寫法 | 常見錯誤 |
|------|---------|---------|
| 背景設定 | `s.background = { color: 'RRGGBB' }` | ~~`{ fill: { color: '...' } }`~~ |
| 形狀名稱 | `pres.shapes.OVAL` | ~~`pres.shapes.ELLIPSE`~~（不存在） |
| 色碼格式 | 6 位 hex，不加 `#` | ~~`'#011c67'`~~ |
| 版面尺寸 | `pres.layout = "LAYOUT_WIDE"`（13.33 × 7.5 inches） | 忘記設定導致 4:3 |
| 字體 | `fontFace: "Microsoft JhengHei"` | 混用不同字體名稱 |
| Shadow | 用 factory function 建立 shadow 物件 | 直接寫 plain object |
| 品牌標記 | 每頁只放一個品牌識別（文字或 Logo，不要兩者都放） | 左上文字 + 右上 Logo 同時出現 |

## 文字陷阱（實戰踩過的坑）

### Rich text 中文標點會在奇怪的位置換行

**問題**：把一句話拆成多個 run（為了不同顏色或粗細），中文標點會被當成獨立可斷點，導致「？」「」」等標點單獨掉到下一行。

```javascript
// ❌ 錯誤：問號可能掉行
s.addText([
  { text: "工作流的一部分", options: { color: "38BDF8", bold: true } },
  { text: "？", options: { color: "FFFFFF" } },
], {...});

// ✓ 正確：把標點合併進同色的 run，或放在強調色 run 裡
s.addText([
  { text: "讓 AI 真的變成", options: { color: "FFFFFF" } },
  { text: "工作流的一部分？", options: { color: "38BDF8", bold: true } },
], {...});
```

**原則**：**一個完整子句（含結尾標點）永遠放在同一個 run 裡**。只在真正要分段的地方用 `breakLine: true`。

### 不要用空字串 breakLine 做間距

```javascript
// ❌ 錯誤：效果不穩定，有時會產生過大留白
[
  { text: "第一段", options: { breakLine: true } },
  { text: "", options: { breakLine: true } },
  { text: "第二段" },
]

// ✓ 正確：用 paraSpaceAfter 控制段落間距
s.addText([
  { text: "第一段", options: { breakLine: true } },
  { text: "第二段" },
], { paraSpaceAfter: 10, ... });
```

### 大字號（>= 150pt）寬度要給足

**問題**：200pt 的 "01" 字樣放進 3.5" 寬度的文字框會被迫換行變成上下兩行。

**原則**：字號超過 150pt 時，文字框寬度至少給 `字號 × 0.05 吋 × 字數`，並預留 20% 緩衝。
例：200pt × 0.05 × 2 = 20，×1.2 = 4.8"，保險起見給 5"。

2. **根據主題判斷**哪個類別最契合，再從該類別挑 2-3 個模型。必要時跨類別搭配（例如分析型 + 說服型形成對比）。

## 閉環頁視覺呼應紀律

某些敘事模型有「前後呼應」的結構特性，閉環頁面必須在視覺上**刻意呼應**，否則閉環感會失效：

| 模型 | 閉環頁 | 視覺呼應要求 |
|------|--------|--------------|
| SCQA | Question 頁 ↔ Answer 回扣頁 | 同樣的深底、同樣的字級、同樣的左側裝飾條、同樣的問句顏色處理 |
| AIDA | Attention 鉤子 ↔ Action 推廣頁 | 若 Attention 用了某個視覺記號（例如大數字），Action 頁要回呼 |
| PDCA | 每個階段的標題頁 | 四張分頁要同構（位置一致、差別只在文字） |
| 設計思維 | 共感 ↔ 測試 | 首末兩頁要用相同的「使用者視角」圖像語言 |

**實作時**：產出藍圖時就要標註「P<N> 與 P<M> 為閉環頁，視覺需呼應」——這樣之後調整其中一頁時才會記得同步調整另一頁。
