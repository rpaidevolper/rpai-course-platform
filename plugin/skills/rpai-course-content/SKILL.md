# RPAI 課程內容腳本產生器

## 概述

本 skill 將**課綱輸入**轉換為**完整可執行的課程內容腳本**，輸出格式為 Markdown，涵蓋：

- 每頁投影片的版型、標題、內容、視覺設計規格
- 每頁對應的講者腳本（逐字稿或關鍵點）
- Demo 操作說明與備用方案
- 互動節奏設計
- 課後帶走工具清單

產出物為討論用 MD 檔，確認後可進入 PPTX 製作流程。

## Step 1：資訊收集

### 1-A 從課綱萃取的必要資訊

| 欄位 | 說明 | 來源 |
|------|------|------|
| 單元名稱 | 每個教學單元的名稱 | 課綱表格 |
| 學習目標 | 每單元的學習產出 | 課綱表格 |
| 教學方式 | 講授 / Demo / 討論 / 實作 | 課綱表格 |
| 分鐘數 | 每單元時間 | 課綱表格 |
| 適用工具 | 課程使用的 AI 工具名稱 | 課綱說明或對話 |
| 受眾特性 | 主管 / 一般同仁 / 種子成員 / 技術背景 | 課綱說明 |
| 教學模式 | 有實作 / 純 Demo / 混合 | 課綱說明或對話 |

### 1-B 必確認的兩個關鍵問題

在展開內容前，若課綱未說明，務必確認：

1. **學員是否實際操作？** 還是純 Demo 觀摩？
   → 影響：實作頁需要有「任務說明」；Demo 頁需要有「講師操作說明框」

2. **受眾定位是否特殊？**（如：種子成員、高階主管、非技術人員）
   → 影響：講者腳本語氣、場景深度、帶走工具設計

## Step 2：內容展開規則

### 2-A 每單元展開為 N 頁投影片

| 單元時長 | 建議投影片數 | 說明 |
|---------|------------|------|
| 10–15 分鐘 | 2–3 頁 | 簡介或過渡單元 |
| 20–30 分鐘 | 4–5 頁 | 標準知識單元 |
| 35–45 分鐘 | 5–7 頁 | 含 Demo 或討論的主力單元 |
| 60 分鐘以上 | 8–12 頁 | 工作坊型單元，需分段設計 |

每單元固定包含：
- **段落分頁**（深色頁，含單元編號浮水印）
- **情境導入頁**（若為 Demo / 實作單元）
- **內容核心頁**（依學習目標數量拆分）
- **單元小結頁**（帶走 2–3 個重點）

### 2-B 每頁投影片的必要欄位

每一頁輸出需包含以下結構：

```markdown
### 第 N 頁｜頁面標題（深色/淺色）

**版型：** [版型名稱，見 §3]
**標題（字級 Bold 色彩）：** [投影片大標]

[內容說明，依版型格式填入]

**講者腳本：**
> [對話感的逐字稿或關鍵講授重點，150–300 字]
```

### 2-C 教學方式對應的頁面設計

| 教學方式 | 頁面設計重點 | 必須包含 |
|---------|------------|---------|
| 講授法 | 清晰的資訊層次，框架 / 圖表 / 對比 | 帶走工具 |
| 案例分析 | 情境描述 + 數據 + 結論 | 「對你的啟發是什麼？」引導問題 |
| Demo 示範 | 步驟流程 + 指令範例框 + Demo 說明框 | 備用方案說明 |
| 小組討論 | 情境設定 + 引導問題 + 計時說明 | 成果分享橋接語 |
| 總結 QA | 三句帶走 + 開放問答 | 課後資源預告 |

> **字級硬規則（對齊 `rpai-pptx-workflow` 第零層）**：以下所有版型的每一個文字元素一律 **bold: true**、字級 **≥ 16pt**——唯一例外是 D2 的 200pt 裝飾浮水印數字。頁尾、徽章、標籤等弱化元素**靠透明度退場，不靠縮小字級**。本節規格與 brand-guidelines 的 Type Scale 不同時，以本節（簡報場景）為準。

## Step 4：講者腳本撰寫規則

### 語氣設定
- **口語化**：像講師在台上說話，不是唸稿
- **具體**：有數字、有場景、有比喻
- **種子成員導向**：若受眾為種子成員，加入「回去如何推廣」的視角
- **示範橋接語**：Demo 頁前必有「我來實際示範」，Demo 中有操作說明，Demo 後有觀察引導

### 講者腳本長度
| 頁面類型 | 建議字數 |
|---------|---------|
| 破冰 / 情境 | 100–150 字 |
| 概念說明 | 150–250 字 |
| Demo 操作 | 200–300 字（含操作說明） |
| 單元小結 | 80–120 字 |
| 課程總結 | 100–150 字 |

### 必備橋接語
- **單元開場：** 「我們從＿＿開始。」/ 「這個單元的核心問題是：＿＿。」
- **Demo 前：** 「讓我切換到＿＿示範。」/ 「我準備好了一份＿＿，你們看。」
- **Demo 後：** 「你看到了什麼？」/ 「這個操作讓你省了多少時間？」
- **單元結尾：** 「帶走一件事：＿＿。接下來我們進到＿＿。」

## Step 5：特殊單元設計規則

### Demo 單元（示範為主）

每個 Demo 必須包含：
1. **情境設定頁**（L1 版型）：讓聽眾代入場景
2. **步驟流程頁**（L3 版型）：說明 Demo 的三步驟
3. **Demo 說明框**（右側 Surface 底色）：操作備忘 + 預計示範時間
4. **觀察引導語**（講者腳本中）：告訴聽眾看什麼

Demo 備用方案規則：
- 若工具需要帳號 / 網路，務必在 Demo 說明框中標註備用方案
- 建議準備「截圖版靜態 Demo」作為備用

### 種子成員特別設計

若課綱說明受眾為種子成員，需在以下位置加入「推廣視角」頁：
- 在前半段（認知建立後）加入一頁：「你學到這個之後，如何跟同事說？」
- 在 Demo 單元後加入「種子成員觀察點」
- 在結語中強調：「你帶回去的不只是工具，是帶頭改變的能力」

### Google AI Studio 單元

固定包含以下三個部分：
1. **定位比較頁**（L2 或 L4）：與主要工具（如 Copilot）的差異說明
2. **使用場景頁**（L3）：3 個金融 / 業務場景的具體用法
3. **Demo 操作頁**（L3 + Demo 框）：介面導覽 + 1–2 個實際示範

## Step 7：輸出格式

### ⚠️ 預設輸出＝精簡版（2026-08 改版）

實測回饋：舊版「每頁完整展開」（版型規格＋內容明細＋整段逐字稿）在 30 頁時會變成 30 大段，**難以閱讀與確認**。因此改為兩層輸出：

**第一層（必產）：逐頁總表** — 一頁一列，一眼掃完全場

```markdown
| # | 頁面標題 | 版型 | 這頁要講的一件事 | 互動/Demo |
|---|---------|------|----------------|----------|
| 1 | 封面 | D1 | — | — |
| 5 | 進入正題：GG 故事 | L1 | 不一致才是痛點 | 暖身投票 |
```

**第二層（必產）：逐頁精簡卡** — 每頁固定三~四行，不再長篇

```markdown
### 5｜進入正題：GG 故事（L1・淺）
- **上牆**：GG 故事卡片＋投票選項四個
- **講稿核心**（≤3 句）：講 GG 故事 → 開投票 → 用結果接三分法。
- **互動/Demo**：暖身投票（Slido）
```

規則：
- 「上牆」＝這頁投影片實際出現的元素，一~兩行
- 「講稿核心」**上限 3 句**，只寫台詞骨幹與轉場鉤子，不寫完整逐字稿
- 沒有互動/Demo 的頁面省略該行
- 完整逐字稿**不放在腳本裡**——它的歸宿是 PPTX 的 speaker notes（由 pptx-workflow 產出時展開）

**第三層（選配）：完整逐字稿附錄** — 僅在使用者明確要求「逐字稿」時，另立附錄或獨立檔案，不混入主腳本。

### 與教學藍圖的一致性義務（2026-08 新增）

- **開工前**：先找教學藍圖（對話中或 outputs 的 `*_教學藍圖.md`）。有 → 讀取其敘事主軸、五元素落點、時間骨架，**不重問**；沒有 → 建議先跑 `rpai-talk-blueprint`。
- **開工中**：若與使用者討論後改動了藍圖層級的決策（工具順序、主軸、段落增刪），**必須先回寫教學藍圖再繼續產腳本**——不同步就繼續，是「藍圖與逐頁不一致」的根因。

## Gotchas（常見陷阱）

1. **Demo 頁不等於操作說明頁**：Demo 頁的重點是「講師說什麼」，操作細節放在 Demo 說明框，不需要列出每個點擊步驟
2. **種子成員 ≠ 技術人員**：種子成員的設計重點是「如何推廣」，不是「如何深入技術」
3. **每單元小結頁不可省略**：這是學員記憶錨點，最多三點，用動詞開頭
4. **Google AI Studio 必須說明與其他工具的定位差異**：不能只介紹功能，要說清楚「什麼時候用它、什麼時候用 Copilot」
5. **講者腳本必須口語化**：避免「本頁將說明…」這類書面語，改用「我們來看一下…」
6. **深色頁不可出現 Ash 背景**：深色頁只有 Navy / Teal / White
7. **淺色頁禁止 Navy 色塊**：Navy 只能是文字或頂部裝飾線（h ≤ 0.07 吋）
8. **Demo 準備清單不可漏**：這是講師備課的重要輸出，少一個 Demo 都不行
9. **總頁數要估算準確**：封面 + 段落分頁 + 內容頁 + 休息頁 + 結語頁，逐一計算
10. **每個單元至少一個互動設計**：即使是純講授，也要有舉手投票或問句引導

| Token | Hex | 使用場景 |
|-------|-----|---------|

2. 淺色頁禁止 Navy 色塊
