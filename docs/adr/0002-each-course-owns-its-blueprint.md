# 每門課程擁有自己的藍圖，知識庫只以複製的方式提供內容

同一套內容幾乎每次都要依客戶調整受眾與產業素材，所以每門課程都有自己的一串藍圖版本，不設一份讓各課程分支或同步的「主藍圖」。過去的課透過知識庫（模組卡、單元卡、課程配方、產業素材包）幫助新藍圖快速談出來：新藍圖誕生時把內容**複製**進來，只記錄每個單元出自哪張單元卡（或哪門課程），以及套用了哪個產業素材包。之後知識庫改版，已經存在的藍圖不受影響。這樣「藍圖是唯一真相來源」對每一門課都成立，產物也能可靠地指向它出生時的那一版藍圖。

## Considered Options

- **每門課只引用一份共用藍圖，換受眾就另開一門課**：每次客製都要開新課，課程數量暴增，而且客製的內容沒辦法回流。
- **主藍圖 + 每門課的分支藍圖**：主藍圖升版時要決定分支要不要跟上，等於在藍圖上做 merge。講師實際上不需要這種同步，代價太高。
- **藍圖引用知識庫（知識庫改了，藍圖跟著變）**：已經發給學員的教材會因為別門課的改動而失去依據，違反「產物綁定藍圖版本」。

## Consequences

- 相似的內容會在多份藍圖中各存一份，這是刻意的取捨。要找出共通的部分，靠的是課程結案後由 AI 拆出單元卡與課程配方草稿、講師審核後收進知識庫（也可以升成既有模組卡的新版），而不是讓藍圖之間互相連動。
- 藍圖要記錄每個單元的來源，知識庫才能統計使用情況，審核時也才能判斷該更新哪張單元卡、升哪張模組卡。
- 新課程也可以用另一門課程的某一版藍圖為底建立（例如從同仁班建主管班），一樣是複製，之後兩邊各改各的。
- 來源記錄在單元層級：每個單元記得它出自哪張單元卡、或哪門課程的哪個單元，或是新做的，以及沿用程度（沿用、要改、新做）。

## 修訂（2026-10-24，#53）

知識庫改用團隊既有的整理方式：

- **儲存單位是單元卡。** 原本的「框架」只記單元標題，現在拆成兩層：每個模組一張模組卡（核心單元骨架，有版本），可重複使用的那一段教學是單元卡。單元來源因此改成「單元卡」或「課程」，不再指向框架。
- **課程配方不是藍圖。** 配方只有單元序列、分鐘數、產業、對象、工具，沒有敘事、學習成果、重點與五元素，所以不轉成藍圖、也不當成過去的課程匯入。新藍圖從配方複製時，只帶過來配方本身有的欄位，其餘由藍圖對話補齊。
- 「情境」改名為「產業素材包」，「主題」由「模組」取代。
