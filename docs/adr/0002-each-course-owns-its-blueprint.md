# 每門課程擁有自己的藍圖，知識庫只以複製的方式提供內容

同一套內容幾乎每次都要依客戶調整受眾與情境，所以每門課程都有自己的一串藍圖版本，不設一份讓各課程分支或同步的「主藍圖」。過去的課透過知識庫（框架與情境）幫助新藍圖快速談出來：新藍圖誕生時把內容**複製**進來，只記錄它來自哪個框架的哪一版、哪個情境。之後框架升版，已經存在的藍圖不受影響。這樣「藍圖是唯一真相來源」對每一門課都成立，產物也能可靠地指向它出生時的那一版藍圖。

## Considered Options

- **每門課只引用一份共用藍圖，換受眾就另開一門課**：每次客製都要開新課，課程數量暴增，而且客製的內容沒辦法回流。
- **主藍圖 + 每門課的分支藍圖**：主藍圖升版時要決定分支要不要跟上，等於在藍圖上做 merge。講師實際上不需要這種同步，代價太高。
- **藍圖引用框架（框架改了，藍圖跟著變）**：已經發給學員的教材會因為別門課的改動而失去依據，違反「產物綁定藍圖版本」。

## Consequences

- 相似的內容會在多份藍圖中各存一份，這是刻意的取捨。要找出共通的部分，靠的是課後由 AI 拆出框架與情境草稿、講師審核後收進知識庫（也可以升成既有框架的新版），而不是讓藍圖之間互相連動。
- 藍圖要記錄來源框架（含版本）與情境，知識庫才能統計使用情況，審核時也才能判斷該升哪個框架的版本。
