# 北極星：讓 RPAI 講師把一門客製課，更快備到可以上課

平台長到有四件事同時被當成核心在做：備課（藍圖與產物鏈）、知識閉環（知識庫與結案回存）、交付營運（專案、場次、準備度、價格）、學員發布（發布與學員入口）。每一件都大到能自成一個產品。現有的核心原則只規定「怎麼做」（藍圖是唯一真相來源、產物綁版本），任何讀藍圖的功能都過得了關，範圍因此一路長大，核心流程卻還沒有一位講師用真實的課走完過。所以我們定下北極星：**讓 RPAI 講師把一門客製課，更快備到可以上課**，做得好的標準是前提只談一次、教材彼此一致、每門課都從團隊最新的版本出發。備課是唯一的核心。知識庫是讓備課與時俱進的機制：它的功能要說得出「讓下一門課的起點更新、更好用」。交付營運與學員發布是外圍，只做到備課需要的程度。

## Considered Options

- **知識閉環是核心**（#78 待決-11 的理由句）：拿掉備課，知識庫只剩一個比資料夾好找的瀏覽器；拿掉知識庫，講師照樣能備課，只是起點比較舊。所以是知識庫服務備課，不是反過來。
- **交付營運或學員發布是核心**：它們各自是另一種產品（專案管理、學習管理系統）。平台獨有的是團隊共用的藍圖與知識，這份價值落在備課上。
- **為外部講師或培訓機構做產品**：知識庫、品牌規範、rpai-* skill 都是 RPAI 專屬。替外部預留，每個決定都要多付多租戶、通用品牌、上手流程的成本。平台是內部工具，要對外時另立 ADR。

## Consequences

- 每張 issue 標一個分類：核心、前提、護欄、外圍，外圍要寫為什麼現在做（CLAUDE.md「北極星」）。
- 備課從講師開口說要備什麼課開始，不必先有專案或客戶背景；到可以上課為止，也就是每一天的簡報、有動手環節那幾天的學員手冊都備好。上完課之後的回存屬於知識庫，是下一門課的起點，不算進這門課的備課時間。
- #78 待決-11 的理由「產品的核心是知識閉環」不再成立。結案草稿讀最終版產物這個做法仍然合理，但由誰產生改依 ADR 0008。
- 第一個基準數字，是 v0 驗收時一門真實課程從開口到產物齊備花了多少時間（#131）。
