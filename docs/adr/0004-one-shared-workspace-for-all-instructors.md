# 全團隊共用一個工作區

講師團隊只有幾個人，彼此代課、共同維護課程；知識庫的價值，就在於讓不熟某個案子的講師也找得到過去的教學內容。所以平台只有一個工作區：每位講師都看得到、也改得了所有專案、課程與知識庫，包含專案價格。這推翻了原本「資料只有 owner 本人可讀寫」的設計。

## Considered Options

- **只共用知識庫，專案與課程各自私有、可邀請共同維護**：要另做邀請與成員管理。但 GLOSSARY 本來就說一門課程可由多位講師共同維護、平台上沒有講師以外的管理角色，私有反而是例外。
- **維持 owner-only**：知識庫只有建立者看得到，失去共用的意義，也擋住「找不到模組內容」這個要解決的問題。

## Consequences

- RLS 與 MCP 工具以工作區過濾（#87，migration `0005_workspaces`）：policy 用 `is_workspace_member(workspace_id)`，MCP 的權杖對到講師所屬的工作區。`owner_id` 保留當「建立者」，不再用來授權。
- 用 service role client 時一樣必須自己加工作區條件，不要相信 RLS 會擋。
- 登入不等於加入工作區：公開註冊關閉，成員由 owner 用 `pnpm member:add` / `pnpm member:remove` 管理；被移除的人權杖立刻失效。
- 專案價格對所有講師可見。
- 平台仍然只有講師一種角色。之後若要讓團隊以外的人（例如客戶或外部講師）進來，另立 ADR。
