# 同步知識庫

知識庫的真相來源是維護者本機的 Markdown 資料夾（格式見 [`specs/2026-10-24-knowledge-base-import-mapping.md`](specs/2026-10-24-knowledge-base-import-mapping.md)）。`pnpm kb:sync` 把資料夾的內容去識別化後同步進平台，講師的 AI 再透過 MCP 的 `rpai_platform_search_knowledge`、`rpai_platform_read_knowledge` 查它。

## 誰來跑、在哪裡跑

- 知識庫維護者在**自己的電腦**上跑。資料夾含客戶名稱，永遠不進 repo，也不要放進雲端 session。
- 需要 `.env.local` 裡的 `NEXT_PUBLIC_SUPABASE_URL` 與 `SUPABASE_SERVICE_ROLE_KEY`（正式環境的金鑰，向 owner 拿）。

## 怎麼跑

先試跑，看報告，不寫入：

```bash
pnpm kb:sync <知識庫資料夾> --aliases <別名檔>
```

報告沒問題再加 `--apply` 寫入：

```bash
pnpm kb:sync <知識庫資料夾> --aliases <別名檔> --apply
```

可以重跑：內容沒變的不動；資料夾裡消失的文件標成退役（不刪除，AI 查不到）；退役後又放回來的會恢復。

報告不列出客戶名稱，檔名裡的客戶名稱也會換成「〔已遮蔽〕」。報告還是含檔名，**不要貼到 issue、PR 或對話裡**。

## 別名檔

一行一個名稱，放在知識庫資料夾旁邊、不進 repo。`#` 開頭是註解；`!` 開頭是「這不是客戶名稱」的例外。

```
# 客戶的簡稱、英文名、產品或專案名稱、外部講師姓名
某客戶簡稱
SomeClient
!RPAI
```

配方的 `client` 欄位與配方 id 裡的客戶段會自動加進名稱表。所有名稱不分長短都比對：英文名（只含英文字母、數字、空白或標點，例如 `GE`、`3M`）只比對完整的詞，所以 `GE` 不會命中 `AGENT`；中文名稱在文字裡任何位置都算命中。誤判時，優先改寫資料夾裡的文字；也可以在別名檔用 `!` 列為例外，但列為例外後，這個名稱在所有文件裡都不再比對。報告會印出 2 個字以下的短名稱有幾個，但不印名稱。

## 同步時拿掉什麼

| 文件 | 拿掉 |
|---|---|
| 課程配方 | frontmatter 的 `client`、`source`、`id`、`title`；「原始檔」「主簡報」兩節；大標題。標題改成「產業・模組・規格」的中性名稱 |
| 單元卡 | `used_in`、`times_used`；「出處」與「講師備註」兩節 |
| 模組卡 | 「產業皮現況」「現況與缺口」「代表課程配方」三節 |

拿掉之後，文字裡還有名稱表裡的名稱的文件會被**暫停使用**：照常同步，但 AI 查不到。報告會列出這些檔案，請在資料夾裡改寫後重跑。

## 硬錯誤

遇到下面的情況，整批都不寫入，照報告修正資料夾後重跑：

- frontmatter 無法解析，或有重複的 key。支援 `key: 值`、`[a, b]` 與 `- 項目` 的清單；縮排的多行文字與巢狀結構不支援。
- 模組卡或單元卡的 `module` 不在 A1–B4，或模組卡的 `id` 和 `module` 不同。
- 兩份文件的來源 id 相同。
- 找不到模組框架文件。

## 其他

- 沒有 frontmatter、或 frontmatter 不屬於四種文件的 Markdown 會略過，例如原始課綱暫存區與說明檔。`.` 開頭的檔案與資料夾也略過（例如 macOS 的 `._` 檔）。
- 程式碼區塊裡以 `#` 開頭的行也會被當成標題處理。
